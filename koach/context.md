## 1. מטרה

ווידג'ט **"קרא וחתום" (קו"ח)** לתוך דשבורד הטייסים של היחידה האווירית (משטרת ישראל).
כשטייס מגיע למשמרת ופותח את הדשבורד, הוא רואה את רשימת הקו"חים האחרונים שהמפקד פרסם,
קורא אותם ומאשר קריאה. המערכת עוקבת מי קרא ומי לא — לצורך "שיימינג" חיובי שגורם לכולם לקרוא.

הווידג'ט משולב בדשבורד באמצעות **iframe** (החבר קרא לזה "INFRAME") — כלומר הוא אפליקציה
עצמאית שמתארחת בכתובת משלה, וה-HTML של הדשבורד מטמיע אותה עם `<iframe src="...">`.

## 3. אתגר ארכיטקטוני מרכזי — צריך Backend

האפליקציות הקיימות ברפו (`h125wb`, `h145wb`) הן **סטטיות לחלוטין** (GitHub Pages, ללא שרת).
קרא וחתום **לא יכול** להיות סטטי, כי הוא דורש **מצב משותף ומתמשך בין משתמשים**:
- אחסון הקו"חים שהמפקד מעלה (טקסט + קבצים)
- מעקב "מי קרא מה" — משותף לכל הטייסים, מסונכרן
- זהות המשתמש (מי אני, האם אני מפקד)

לכן צריך שכבת backend + אחסון קבצים + זהות.

### המלצה: **Firebase** (חבילת Google)
- **Firestore** — DB בזמן אמת לרשימת הקו"חים + מטריצת "מי קרא מה"
- **Firebase Storage** — אחסון קבצי ה-PDF/Word
- **Firebase Auth** — זהות טייס (Google / Email) + הרשאת מפקד
- שכבה חינמית נדיבה, סנכרון בזמן אמת (חשוב לסימון ירוק/אדום שמתעדכן חי), אין להחזיק שרת
- חלופה: **Supabase** (Postgres + Auth + Storage) — אם מעדיפים SQL

> ⚠️ **הערת אבטחה (הקשר משטרתי):** מסמכים רגישים. לפני production צריך להחליט על ריבונות מידע,
> הרשאות, ואולי אחסון בתוך רשת היחידה במקום ענן ציבורי. לפרוטוטייפ — Firebase מספיק.

### נגזרות אבטחה מההחלטות (חשוב!)
1. **אמון בזהות = קריטי.** הדשבורד חייב להעביר **JWT חתום** (עדיף דרך `postMessage`, לא ב-URL), וה-backend
   חייב **לאמת את החתימה** לפני רישום "קראתי". אחרת אפשר לזייף חתימת קריאה. חתימת קו"ח = בלתי ניתנת להכחשה.
2. **עדיף שה-backend של הדשבורד יחזיק את המידע.** אם למערכת האב כבר יש backend/API — הקו"חים ומטריצת
   "מי קרא" צריכים לשבת שם (אותו גבול אמון, אותה ריבונות), במקום דאטהבייס ענני נפרד עם עותק שני של מסמכים רגישים.
3. **שיימינג = חשיפה מכוונת בתוך קבוצת הטייסים** (by-design, בסדר). הרגישות היא בתוכן המסמכים ובגישה מאומתת בלבד.

### 4.1 מודל זהות — Session משותף (החלטה מרכזית)
הווידג'ט מוגש **מאותו domain** של הדשבורד. לכן:
1. הטייס מתחבר לדשבורד → PHP יוצר `$_SESSION`.
2. ה-iframe נטען מאותו origin → הדפדפן שולח אוטומטית את אותו session cookie.
3. קוד הקו"ח קורא `$_SESSION['user_id']` → מזהה בוודאות מי הטייס, **בלי אפשרות זיוף**.

⚠️ **דרישת אינטגרציה:** ה-iframe חייב להיות same-origin (אותו domain, או subdomain עם `SameSite`/cookie מתאים),
אחרת דפדפנים חוסמים third-party cookies והזהות תישבר. זהות דרך פרמטר GET = **פסולה** (ניתנת לזיוף).
אם בעתיד SSO — הוא יזהה מול הדשבורד, וה-session ימשיך לעבוד אותו דבר.

> ⚠️ **סיכון: PHP 5.3.13 = EOL מ-2014** (אין עדכוני אבטחה כבר ~10+ שנים, גרסה ישנה אף יותר משהוערך בשיחה קודמת).
> לא חוסם (כותבים קוד תואם 5.3 + prepared statements), אבל סיכון אבטחה אמיתי למערכת משטרתית — לשקול שדרוג PHP.
> ה-login ממילא באחריות הדשבורד, לא הווידג'ט — אבל `password_hash()` (מ-5.5) ו-`array_column()` (מ-5.5) פשוט
> לא קיימים כאן; ראה מגבלות תחביר מדויקות בסעיף 4.1.1.

### 4.1.1 מגבלות תחביר PHP 5.3.13 (חשוב לכל קובץ שנכתוב)
גרסה זו **קודמת** ל-PHP 5.4/5.5 — כמה תבניות מודרניות **לא זמינות** ויגרמו ל-Parse error:
- ❌ **אין short array syntax** `[]` — חובה `array(...)` בכל מקום (גם ב-`json_decode`, פרמטרים, וכו')
- ❌ **אין traits**, אין `function array dereferencing` (`foo()[0]`)
- ❌ **אין `password_hash()`/`password_verify()`** (נוספו ב-5.5) — אם נצטרך האשינג בעצמנו: `crypt()` עם `CRYPT_BLOWFISH`
- ❌ **אין `array_column()`** (5.5) — לכתוב לולאה ידנית
- ✅ יש `mysqli` (prepared statements), `namespace` (מ-5.3), `closures`/`function()use(){}` (מ-5.3), `?:` (מ-5.3)
- כללי אצבע: לכתוב הכל כאילו זה PHP 5.2/5.3 — לבדוק כל פיצ'ר "נוח" מול טבלת [PHP Supported Versions] לפני שימוש

### 4.2 המרת Word→PDF (הוחלט: המפקד מעלה Word, הטייסים תמיד רואים PDF)
כדי שכל הטייסים יראו תצוגה **אחידה** (לא תלוי אם הדפדפן/מכשיר יודע לפתוח .docx), הקו"ח מומר ל-PDF
**פעם אחת, בזמן ההעלאה** ע"י המפקד — לא live בכל צפייה. הקובץ המקורי (.docx) נשמר גם הוא (ליכולת הורדה/ארכיון).

**מנגנון מוצע:** LibreOffice headless בשרת:
```bash
soffice --headless --convert-to pdf --outdir /uploads/koach/ /uploads/koach/original.docx
```
מופעל מ-PHP דרך `shell_exec()`/`exec()` בזמן `upload.php`. דורש ש-LibreOffice מותקן על שרת הדשבורד.

🔴 **שאלה פתוחה לתחילת שיחה 4:** האם מותר/אפשר להתקין **LibreOffice** על שרת הייצור של הדשבורד?
אם לא — האלטרנטיבות: (א) ספריית PHP להמרה (PhpWord ליצירה, לא המרה איכותית) — פחות נאמן למקור;
(ב) שירות המרה חיצוני (ענן) — נשלל ברוב המקרים בהקשר משטרתי (ריבונות מידע, סעיף 3); (ג) המרה
ב-worker נפרד/מבודד ברשת הפנימית, לא בשרת הדשבורד עצמו. ברירת מחדל: LibreOffice headless, בהנחת אישור.

## 5. מודל נתונים — MySQL (MySQLi)

```sql
-- טבלת קו"חים
CREATE TABLE koach (
  id             INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  title          VARCHAR(255) NOT NULL,
  type           ENUM('file','text') NOT NULL,   -- 'file' = תמיד מוצג כ-PDF (גם אם המקור docx)
  body           MEDIUMTEXT NULL,                -- אם type=text: התוכן. אחרת NULL
  pdf_path       VARCHAR(500) NULL,               -- נתיב ה-PDF להצגה (מקורי או ממומר)
  original_path  VARCHAR(500) NULL,               -- נתיב הקובץ המקורי (docx/pdf) לארכיון/הורדה
  created_by     INT UNSIGNED NOT NULL,    -- user_id של המפקד (מטבלת המשתמשים של הדשבורד)
  created_at     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- מי קרא מה (חתימת קריאה)
CREATE TABLE koach_reads (
  koach_id  INT UNSIGNED NOT NULL,
  user_id   INT UNSIGNED NOT NULL,      -- מ-$_SESSION, לא ניתן לזיוף
  read_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (koach_id, user_id),
  FOREIGN KEY (koach_id) REFERENCES koach(id) ON DELETE CASCADE
);
```

- **רוסטר הטייסים + מי המפקד** — מגיעים מטבלת המשתמשים **הקיימת** של הדשבורד (לברר שם טבלה + שדה role/rank).
  לא יוצרים טבלת משתמשים כפולה. מפקד = role/דגל בטבלה הקיימת.
- **חוק הצגה (דרישה 6):** `5 האחרונים לפי created_at` ∪ `{כל קו"ח שאין לו שורת read ל-user_id הנוכחי}`.

### Endpoints מתוכננים (PHP, כולם בודקים `$_SESSION`)
| Endpoint | מי | פעולה |
|----------|-----|-------|
| `GET  list.php` | כל טייס | מחזיר את רשימת הקו"חים לפי חוק ההצגה + סטטוס קריאה שלי |
| `GET  view.php?id=` | כל טייס | מחזיר PDF/טקסט לתצוגה (בדיקת session לפני הגשת קובץ) |
| `GET  download.php?id=` | כל טייס | מוריד את הקובץ המקורי (docx/pdf) אם קיים |
| `POST read.php` | כל טייס | רושם `koach_reads` ל-user_id מה-session |
| `GET  readers.php?id=` | כל טייס | מי קרא / מי לא (ל-tooltip השיימינג) |
| `POST upload.php` | **מפקד בלבד** | יוצר קו"ח (טקסט/קובץ). בודק role=commander |

## 9. יומן שיחות

### שיחה 1 (יולי 2026) — תכנון
- מיפוי הרפו הקיים (מונו-רפו, 2 אפליקציות סטטיות)
- זיהוי שקו"ח דורש backend (שינוי ארכיטקטוני מרכזי)
- כתיבת קובץ context זה + תכנית עבודה 7 שלבים
- **לא נבנה קוד עדיין** (לבקשת הלקוח)
- **החלטות שהתקבלו:** ריפו חדש נפרד ✅ · זהות מהדשבורד ההורה ✅ · backend פתוח (דיון אבטחה)
- **דיון אבטחה:** צורך ב-JWT חתום מהדשבורד; עדיפות שה-backend של הדשבורד יחזיק את המידע; ריבונות מידע

### שיחה 2 (יולי 2026) — קביעת ארכיטקטורה
- **תשתית הדשבורד נחשפה:** PHP 5.4 (תוקן בשיחה 3 ל-5.3.13) + MySQLi, login TBD (מסך login/GET/SSO בהמשך)
- **הוכרע:** Backend = PHP+MySQLi על אותו שרת · Frontend = Vanilla JS (בלי build) · הטמעה = iframe same-origin
- **זהות = `$_SESSION` משותף** (same-origin) — פשוט ומאובטח יותר מ-JWT/GET; GET נפסל (זיוף)
- עודכנו: מחסנית (סעיף 4+4.1), מודל נתונים MySQL + endpoints (סעיף 5), Phase 1
- **סיכון שנרשם:** PHP EOL (גרסה מדויקת תוקנה בשיחה 3 ל-5.3.13, EOL מ-2014)
- **לברר מול צוות הדשבורד:** שם domain (לוודא same-origin ל-iframe) · שם טבלת המשתמשים
  ושדה role/מפקד · מפתח ה-session (`$_SESSION['?']`) · היכן uploads/ · האם login כבר קיים או שנחכה ל-SSO
- **עדיין לא נבנה קוד** (לבקשת הלקוח — תכנון בלבד)

### שיחה 3 (יולי 2026) — סגירת 3 שאלות מוצר פתוחות
- **הוכרע:** Word שהמפקד מעלה → **תמיד מוצג כ-PDF** לטייסים (המרה חד-פעמית בזמן ההעלאה, לא live).
  מנגנון מוצע: LibreOffice headless (`soffice --convert-to pdf`) מופעל מ-PHP. **שאלה פתוחה:** האם מותר
  להתקין LibreOffice על שרת הייצור (סעיף 4.2) — אם לא, צריך לבחור חלופה.
- **הוכרע:** השיימינג מציג **שמות מלאים** (לא רק ספירה/אחוזים) — לחץ חברתי מקסימלי, כמבוקש.
- **הוכרע:** קו"ח שלא נקרא מסומן **אדום בלבד** — לא חוסם את הדשבורד, אין "קריאה מחייבת" שמונעת כניסה.
- עודכנו: דרישות מוצר (סעיף 2), מחסנית + סעיף 4.2 חדש (המרת Word→PDF), מודל נתונים (`pdf_path`/`original_path`
  במקום `type` עם docx, endpoint `download.php` חדש), Phases 2-4
- **עדיין לא נבנה קוד.** חוסם הבא: תשובות "לברר מול צוות הדשבורד" (למעלה) + אישור התקנת LibreOffice
- **תיקון בהמשך אותה שיחה:** גרסת PHP המדויקת היא **5.3.13** (לא 5.4 כפי שנרשם ב-שיחה 2) — נמוכה יותר,
  עם מגבלות תחביר נוספות (ראה 4.1.1: אין `[]`, אין `password_hash`, אין `array_column`)
